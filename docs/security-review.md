# Security review (N39 first pass, N62 second pass)

Scope of this pass: browser-facing headers, the upload serving path, and a check of the other protections the README claims against the code and tests that already exist. It is a review by the builder, not an audit by a third party.

## Findings

| #   | Finding                                                                                                                                                                                                              | Status                                                                                                                                                             |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | No Content-Security-Policy, framing, referrer or MIME-sniffing headers on pages, the admin or the API (only uploads had their own).                                                                                  | Fixed: `securityHeaders` middleware, tested, outermost so cached pages get it too.                                                                                 |
| 2   | No `Strict-Transport-Security` over HTTPS.                                                                                                                                                                           | Fixed: sent on HTTPS (or a trusted `X-Forwarded-Proto`), off with `HSTS=off`.                                                                                      |
| 3   | No dependency audit in CI.                                                                                                                                                                                           | Fixed: a non-blocking `audit` job reports high and critical advisories for production dependencies; Dependabot proposes weekly updates for npm and GitHub Actions. |
| 4   | No `SECURITY.md`.                                                                                                                                                                                                    | Fixed: reporting route, what is protected, known limits.                                                                                                           |
| 5   | The CSP allowed inline styles (`style-src 'unsafe-inline'`) because themes and the editor used them.                                                                                                                   | Fixed in N66: the default policy is `style-src 'self'`.                                                                      |
| 6   | Rate limits (login, contact form) are in memory per process.                                                                                                                                                         | Documented in `SECURITY.md`. A shared store is future work for multi-instance deployments.                                                                         |
| 7   | Plugins are trusted code; permissions are declared, not enforced, except `database`.                                                                                                                                 | Documented in `SECURITY.md` and the plugin screen text; sandboxing is out of scope for 1.0 (see PLAN.md).                                                          |
| 8   | The first audit run found advisories in `zod` (memory exhaustion on oversized collections, high) and `drizzle-orm` (SQL injection through improperly escaped identifiers, high; fixed in 0.45.2), plus one moderate. | `zod` fixed (4.6.6). `drizzle-orm` upgraded to 0.45.2 or later with `drizzle-kit` 0.31. The moderate advisory is open (N62).                                       |

## Second pass (N62)

Scope: every API route's checks, the admin app's output encoding, the importers (WordPress export, zip, CSV, backup JSON) with hostile input, and the audit job. Tests are in `apps/server/src/route-guards.test.ts` and `packages/core/src/hostile-input.test.ts`.

| #   | Finding                                                                                                                                                                                                                                                                | Status                                                                                                                                                                                                                                                             |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 9   | The HTML reader used by the WordPress import matched every `<` that was never closed against the whole rest of the text: `<p<p<p…` took seconds at 100 KB and grows with the square of the size (exports can be 64 MB). An unclosed `<!--` had the same shape.         | Fixed: tag bodies cannot contain a bare `<`, comments are removed in one pass. Tested with quadratic inputs.                                                                                                                                                       |
| 10  | Pages that are each other's parent (or whose parent chain loops) were imported about 50 times each.                                                                                                                                                                    | Fixed: an item is marked placed before its parents are visited. Tested with a two-page loop and a page that is its own parent.                                                                                                                                     |
| 11  | The import kept links such as `java<TAB>script:alert(1)` as relative addresses. Browsers ignore tabs and line breaks inside an address, so such a link is a `javascript:` link. Drawing a page already refused it (`safeUrl`), but API clients read the stored blocks. | Fixed: an address with control characters is dropped at import. The drawing check stays as a second layer. Tested.                                                                                                                                                 |
| 12  | Route checks were reviewed route by route, but only per feature in tests.                                                                                                                                                                                              | A test now builds the app with every feature, calls each registered route without credentials (must be 401 unless on a short public list) and as a subscriber (management routes must be 403, other writes refused). A new route that forgets its checks fails it. |
| 13  | Admin output encoding: no `dangerouslySetInnerHTML`, `innerHTML`, `document.write` or `eval` in the admin or the editor; image and frame addresses come from the server.                                                                                               | Nothing to fix. Keep it so: React escapes everything else.                                                                                                                                                                                                         |
| 14  | Backup JSON with `__proto__` or `constructor` keys, wrong types, oversized lists, very deep or very large bodies.                                                                                                                                                      | Nothing to fix: refused or imported as plain data; tested that prototypes stay clean and that it stays quick.                                                                                                                                                      |
| 15  | The audit job did not block merges.                                                                                                                                                                                                                                    | Fixed: `continue-on-error` removed; the job fails on high or critical advisories in production dependencies. No such advisory is open.                                                                                                                             |
| 16  | The CSP still allows inline styles.                                                                                                                                                                                                                                    | Not done in this pass; task N66 (needs changes in the admin build, both themes and the customizer).                                                                                                                                                                |

## Checked and found as claimed

- Uploads (`createUploadsHandler`, `MediaService`): only `uploads/` keys with a known extension are served, with `nosniff`, `default-src 'none'; sandbox` and immutable caching; PDFs are `attachment`; the stored type comes from the bytes, mismatches are refused, and size and pixel limits apply.
- Cookies, CSRF and login limits: covered by the existing auth tests.
- Redirect rules and the WordPress import map: tested against `//host` and reserved paths.

## Not covered

Fuzzing beyond the hostile cases above (for example with a coverage-guided fuzzer), the plugin zip reader against real-world malformed archives (its limits and path checks are tested in `zip.test.ts`), and sandboxing plugins (out of scope for 1.0).
