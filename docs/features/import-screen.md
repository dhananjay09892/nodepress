# Import screen

The admin **Import** screen (`manage_options`) runs the WordPress import (`POST /api/v1/import/wordpress`) without a command line. The sidebar entry appears when `GET /api/v1/import/wordpress` answers (it returns `{ maxBytes }`, 403 without permission, 404 when the importer is off). Choose the `.xml` file from WordPress (Tools, Export, All content): the browser refuses other file types, empty files and files over the server's limit (64 MB) before anything is sent. Authors are matched to existing users by email (switch this off to give everything to one user), and anything unmatched goes to the chosen user, by default the person running the import. After the run the report lists what was imported (posts, pages, categories, tags), authors matched, links updated, redirects saved (the old addresses of imported items, so old links keep working), files listed in the export but not downloaded yet (N59), and every skipped item, redirect that could not be saved and warning with its reason. Only one import runs at a time; a second answers that one is still running. Imported content is added next to what exists; nothing is changed or deleted.
