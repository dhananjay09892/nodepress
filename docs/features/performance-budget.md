# Performance budget

CI enforces two budgets (N41). Cached pages must answer fast: the smoke job runs `node apps/server/dist/perf-cli.js <base-url> [path ...]` against the running site, which requests each path once to fill the page cache and then 30 more times, and fails when a path does not answer `200`, is not served from the cache (`X-NodePress-Cache: hit`), or has a median or 95th percentile time to first byte over 100 ms. CI checks `/`, a published page, `/sitemap.xml` and `/feed.xml`. `PERF_BUDGET_MS` and `PERF_SAMPLES` change the budget and the number of requests; the command exits with 1 on a breach and 2 on a usage mistake. Aurora's Lighthouse run (blog and business layouts, light and dark) now requires a performance score of at least 95 as well as accessibility. The numbers come from a shared CI runner, so a budget failure means "look at it", not a precise benchmark; the logic lives in `apps/server/src/perf.ts` and is unit tested with a fake clock.
