# WordPress import endpoint

WordPress import: `POST /api/v1/import/wordpress` (`manage_options`; session with CSRF token or Bearer token) takes a WordPress export file (WXR) as the body (`Content-Type: application/xml` or `text/xml`, up to 64 MB) and answers with the import report (counts, WordPress id to NodePress id map, skipped items, warnings, the files that were not downloaded). Items go to the user whose email matches the WordPress author, else to the user running the import (or to `?default_author=<user id>`); `?match_authors=false` gives everything to that one user. The old URLs in the export are saved as 301 redirects (`redirectsSaved`; rules for paths that already have a rule are left alone), so old links keep working. One import runs at a time (`409` otherwise), and a bad item is skipped without stopping the rest. Media download and an admin screen are N59 and N60.
