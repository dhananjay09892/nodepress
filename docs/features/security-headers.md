# Security headers

Security headers: every response gets a Content-Security-Policy (scripts, frames, forms and `<base>` limited to this site; images from this site, `data:`, `blob:` and https; no inline styles: `style-src 'self'`), `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy`, `Permissions-Policy` and `Cross-Origin-Opener-Policy`, plus `Strict-Transport-Security` when the request came over HTTPS (or `TRUST_PROXY=true` and `X-Forwarded-Proto: https`). A header a route sets itself (uploads) is kept. `CONTENT_SECURITY_POLICY` replaces the policy (`off` sends none, for a proxy that sets its own) and `HSTS=off` turns HSTS off. A theme or plugin that needs scripts from elsewhere must be allowed through `CONTENT_SECURITY_POLICY`. See [SECURITY.md](./SECURITY.md) and `docs/security-review.md`.
